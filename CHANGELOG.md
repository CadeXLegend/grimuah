## [Unreleased]

### ⚠ BREAKING CHANGES

* biome is gone. `grimuah check` no longer takes `--biome` and spawns no subprocess, and `init` writes no `biome.json` and no `.grimuah-rules/` directory. A project that wants biome's own recommended ruleset now runs biome itself, and a project that wants the old GritQL plugin files keeps its own copy. The generated `package.json` drops the `lint` and `format` scripts in favour of `check` running `grimuah check`, and the generated husky hook drops `pnpm lint` and `format-on-commit.sh`.

### Features

* add `grimuah skills list` and `grimuah skills install`: the binary carries the five agent skills the repository ships under `skills/`, so a project can hand an agent the same procedures a reader of the repository gets, with no network and no checkout. `list` prints every skill with the sentence an agent matches on, and `install [name...] [--path <dir>] [--force]` writes each one to `<dir>/<name>/SKILL.md`, defaulting to `.agents/skills`, which is the tree agent tools read. an existing file is kept unless `--force` is passed, so a hand-edited or older copy survives a re-run after an upgrade. the markdown is embedded rather than read from a sibling directory, so an installed binary hands over the version it shipped with, and an e2e check compares every installed file against the tree byte for byte so a skill added to `skills/` and never embedded fails there
* add `no-renamed-duplicate-body`: the accepted rule for an identical body keys a declaration on its name beside its body, which is what makes it exact and also why a copy whose author renamed the declaration is invisible to it: the two files hold one implementation under two names, a search for the helper finds only the copy that kept the name, and the copies drift one bug report at a time. the verdict is the run's, and it is the accepted rule's own grouping read the other way: the run's bodies are grouped by their collapsed text alone, and a group two or more files declare under two or more names is a renamed copy, reported at every declaration that holds it. a group whose declarations all keep one name belongs to the accepted rule rather than to this one, a group of one file is no defect, and a body under thirty collapsed characters is no group at all. a `.smoke.ts` contributes no copy to the grouping and reports no row of its own, because the bodies it groups are the accepted rule's collection and that rule reads a smoke module like any other file, so this one excludes it at both ends instead. a body whose defect the computation rule already names stays quiet, which is the detector's own suppression read backwards: a site is inside every body that encloses it, the detector's walk from the body descends through a nested declaration to the site, and it begins at the body itself for an arrow's expression body, so a site marks its own body, each body between it and the group, and the bodies above them. the row names the declaration, how many times the run writes the body, across how many files, the other names it is declared under, and one of those files
* add `no-duplicated-computation`: the same expression written into two modules is one decision written twice, and nothing marks the two copies as related: the compiler sees two independent expressions, a search for a call by name finds neither, and a change to the unit, the rounding or the route has to be found and applied in both. a site is a call, a `new` or a template of seven or more TypeScript descendants, which is the detector's own floor, and only the largest expression of a chain is a site, so a repeat of `a + b` stays silent and a sub-expression of a counted site is not a second finding. the count is the hard half: the front-end's IR is deliberately shallow in expression position, so it now records, per node, the TypeScript descendants the tree does not carry (a member access's dropped name, a binary expression's operator token, a conditional's two tokens, an object entry's key, every type annotation's nodes) and sums that delta over a subtree on demand rather than folding a total in when a node is linked, because the front-end attaches a class member, a catch clause and an object method before it populates them. a type is the one hole a count cannot be taken from directly, so the extent the parser skips is read back by a descent over the type grammar that counts the nodes TypeScript builds there. a `.smoke.ts` is out of scope twice over, exactly as the detector excludes it, and a site inside a body `no-duplicated-function-body` already reports stays quiet, because a reader who fixes the body has fixed the computation with it. the row names the expression and how many other files write it
* add `no-literal-duplicating-config-value`: a literal that retypes a value the surface's own `.config.ts` already declares is a second copy of a single source of truth the compiler cannot keep in step, so changing the enum silently leaves the literal comparing against the old text, and a reader cannot tell whether the match is deliberate or whether it used to be a different value. the pair is found by name rather than by directory: the consumer's own path minus `.ts` is the surface, and the config's path minus `.config.ts` is the same surface when the two share a stem, so `afk.service.ts` reads `afk.service.config.ts` and a directory neighbour's values never match. the enum's members come off the token stream, because the front-end models `enum` as one childless declaration and keeps no member: the walk finds the keyword wherever it stands, a `declare module` block included, and reads a member only when a top-level `=` is followed by a literal, which is the detector's own two gates. a member boundary is a comma or a semicolon, because TypeScript flags a semicolon as a parse error and recovers with both members intact, so `node.members` holds both while a comma-only split lost the second member's value. a `.config.ts` and a `.d.ts` are skipped whole, and a surface with no config of its own reports nothing. the row names the member the value belongs to
* add `no-repeated-inline-copy`: the cross-file copy rule only sees a sentence once it has spread to three files, so the smallest and most common form of the defect is invisible: two statements in one file carrying the same sentence, where a wording change updates one of them and leaves the other saying something the author no longer means. this is the only rule of the literal group with no index at all, because the detector's verdict is the file's: its occurrences are grouped as the file is read and no other file of the run can change the answer. a literal is a site when it is a `StringLiteralLike` of 8 UTF-16 code units or more that holds whitespace and ends in `.`, `!` or `?`, which is the project's own marker for a sentence rather than a log line, and every occurrence is reported once the file holds two. a `.config.ts` and a `.d.ts` are skipped whole, which is the detector's own pair of exclusions: the first is where the sentence belongs rather than where a repeat is a duplicate, and the second declares no copy at all. an import statement's specifier is excluded by the literal's parent, which the tree gives: the front-end consumes a specifier into the statement's own name and builds no node for it, so the specifier is the only literal whose token lies inside an `import_decl`
* add `no-duplicated-user-facing-copy`: one sentence written out in three or more files drifts the moment one site is edited, the reader cannot tell whether two identical sentences are the same message or two messages that happen to match today, and a wording change becomes a search across the codebase instead of one edit at the owning constant. the verdict is the run's rather than the file's: the index counts the DISTINCT FILES that write each sentence, so one file that writes it twice counts once, and every occurrence in a file that is judged is reported. a literal is a site when it is a `StringLiteralLike` (so a backtick literal with no substitution is one and a template that holds a substitution is not), is at least 24 UTF-16 code units long, and holds two letters around a space. a `.d.ts` is excluded at REPORT time rather than at collection, which is the detector's own shape: a declaration file's copy counts toward the sentence's files while producing no row itself. the threshold is three rather than two because two files that mirror each other's copy across a process boundary are deliberate
* add `no-duplicated-statement-text`: the same SQL statement written twice is two contracts that drift apart, and the repeat is invisible to every other duplication check because the two call sites share a handle named for a different table and the statement text is the only part they have in common. the verdict is the run's rather than the file's, and the project pass counts OCCURRENCES rather than distinct files, so a single module that writes the same statement twice holds the whole defect. a literal is a site only when its cooked value opens with `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `WITH` or `REPLACE` on a word boundary, a backtick literal with no substitution is no site at all, and the key is the cooked text with its whitespace folded, so two copies that differ only in how they are wrapped, or only in the escapes they spell their whitespace with, are one statement. a differently cased copy is a second statement, because the keyword match is case-insensitive and the key is not. every copy is reported, on the literal's own line rather than on the call that prepares it. this is the second rule of the text-fingerprint group, and its sites come off the token stream rather than out of a tree, because a tree walk loses a literal-union member
* add `no-duplicated-function-body`: a function whose body is byte-identical to a function of the same name in another file is one implementation written twice, so a fix has to be found in both copies and the copies drift one bug report at a time. the verdict is the run's rather than the file's, because an identical body is a fact about every file, and the project pass keys each declaration on its name beside its collapsed body text, so the whitespace a body is written with never hides the repeat. a class method, an object literal's method, an anonymous default export, a destructured declarator, a body under 30 collapsed characters and two identical declarations inside one file are all out of scope, and the row lands on the body's own line rather than on the declaration's. this is the first rule of the text-fingerprint group, and the first whose index copies text rather than names
* add `no-export-without-consumer`: an exported binding no other module of the project names promises an audience that does not exist, so the `export` keyword states a contract nothing can answer and the declaration is really module private. the verdict is the run's rather than the file's, because whether another module names a symbol is a fact about every file, and the project pass counts the files that spell each name: a name one file writes twenty times still counts once. the scope is the suffixed-module name, two dots or more, so a `.config.ts`, a `.types.ts` and a `.spec.ts` are all read and the tree's own top level is too, which is where this rule and `require-enum-in-config-file` part company. a `.d.ts`, a module with no suffix, `export * from`, `export type { }` from`, an anonymous default export and a destructured binding are all out of scope, one export per declarator is reported, and the row lands on the declared name's own line rather than on the keyword's
* add `require-shared-type-placement`: a type alias an implementation module exports and another directory imports is coupled to that module's behaviour, so it belongs in the surface's `.types.ts` file. a consumer in the same directory does not count, an enum is `require-enum-in-config-file`'s own case, and a declaration module, a module with no behaviour kind and a renamed import are all out of scope. a module at the top of the tree is read, which is where this rule and the enum rule part company
* add `no-redundant-allowed-import`: an `allowedImports` entry naming a surface at a lower dagOrder is a grant the dag already makes, so `canImport` never reads it and the entry is dead configuration. the row lands once per surface, at the surface's first file in byte order, and a file inside a nested surface whose own list is empty is judged by the enclosing surface's list, which is the list the checker reads. an entry at the surface's own dagOrder, an entry naming no declared surface and a surface carrying no list are all out of scope. this one reads the project's configuration rather than its sources, so the frozen corpus cannot carry it: an e2e check writes the entry into a scaffold instead
* add `no-import-cycles`: two files that import each other are a cycle, even inside one surface, because a cycle makes module initialisation order load-bearing and lets a value read at module scope be undefined depending on which file the runtime reached first. this one is **error** severity, so it fails a build. the whole project's import graph is resolved before any verdict: a bare specifier, a path outside the source roots, a self-import, a dynamic `import()` and `export ... from` are all no edge at all, and a file reports its own first import that points back into its own component
* add `require-enum-in-config-file`: an exported enum in an implementation module is a configuration constant declared in the wrong place, because every consumer imports the module that owns the behaviour to read the vocabulary. a bare `export enum`, an `export declare enum` and an `export const enum` are all read, an `export` on a line of its own reports on that line, and an unexported enum, an enum inside a `declare module` block or a bare block, a `.config.ts`, a `.types.ts`, a `.d.ts`, a module with no behaviour kind and a module at the top of the tree are all out of scope. this is the first rule of the import and export graph group, and the first that reads a module's name as well as its declarations
* add `no-discarded-outcome`: a call that returns an Outcome may not be a bare statement, because the result is dropped before it is read and the failure branch becomes unreachable. the callee's declaration is looked up across the whole project, a member access by its last name, and a name two declarations disagree about is not reported
* add `no-unread-scalar-result`: a call whose declared result is `Promise<boolean>` or `Promise<number>` must have that result read. `void f()` states the dropped result on purpose, so it is reported as the same defect, and an assignment, a `Promise<void>` result and a disagreement between two declarations of one name are out of scope
* add `no-async-scalar-failure-return`: an exported async operation must not report its failure as a bare boolean or number, so a result declared `Promise<boolean>` or `Promise<number>` is what it reports on. a function declaration, an arrow and a function expression are all read, and an unexported operation, a non-async one and a result of any other type are out of scope
* enforce every rule in-process and freeze the findings biome validated in `tests/oracle/`, so the corpus check runs without biome
* add `require-enum-over-literal-union`: a union of two or more string literals must be a string enum. a type alias, a property, a parameter and a variable annotation are read, and a return annotation is not. the module has to be named `<name>.<kind>.ts`, because a process entry script cannot use an enum at runtime
* add `no-optional-properties`: an object type may not declare an optional property. an interface, a type literal, an `as` assertion's type and a `declare module` block are read, and an optional parameter, a class field and an optional method are not
* add `require-readonly-collection-signatures`: a parameter, a return type and an object type's property must not be a mutable array. a class field, a type alias and a local binding are out of scope, and `readonly T[]`, `ReadonlyArray<T>`, `undefined | T[]` and `() => T[]` are all left alone
* add `require-readonly-type-members`: every property of a type literal must be `readonly`. an interface's properties are never reported, which is the detector's own narrowing rather than an oversight
* add `any-type`: `any` used as a type is an error, wherever it stands: `: any`, `any[]`, `Array<any>` and a return annotation. `o.any` and `{ any: 1 }` are names rather than types, and the `as any` cast keeps its own message
* add `max-nesting-depth-three`: a statement container may not nest more than three layers deep inside one function, method or class body
* add `max-parameters`: a function may not declare more than four parameters, counted from the signature so a destructured parameter stays one slot
* add `require-capitalised-user-facing-copy`: user-facing copy in a `.config.ts` file must start with a capital letter
* add `no-boolean-flag-argument`: a call may not pass a bare `true` or `false`
* add `max-function-lines`: a function body may not run past 80 lines
* add `no-nested-ternary`: a conditional expression may not contain another one
* add `max-file-lines`: a module may not run past 500 lines, and a `.d.ts` file is out
* add `no-await-in-loop`: an `await` in a loop body serialises its iterations
* add `max-cyclomatic-complexity`: a function may not hold more than 15 independent paths
* add `require-limit-on-collection-reads`: a query that reads a collection must carry a LIMIT
* add `no-for-of-push-accumulation`: a `for..of` loop may not build an array by pushing into it
* add `config-declares-data-only`: a `.config.ts` file may declare data, never a function
* add `no-if-chain-dispatch`: a run of three or more branches over one subject is a dispatch table
* turn a single rule off by name: every rule of the table carries a name (`em-dash`, `switch-statement`, `prefer-const`), and `architecture.config.json` gains a flat `rules` object that silences one rule without giving up the rest of its layer, where the layer toggle was the only switch before. a rule the object omits runs, so a config lists only what it silences. the layer stays the gate rather than the rule: a rule named on inside a layer that is off stays off. a name the table does not have stops the run with the name it could not match, because a typo would otherwise leave the rule it meant to silence reporting. `grimuah rules` prints every name grouped by layer with its severity and the sentence it reports, and `architecture.schema.json` lists the same names, so an editor autocompletes the key and marks a typo before the run does. the surface and edge model is not a rule: the suffix list, the import firewall, the dag order and the innate member scoping are the declaration a project makes about itself, and their layer is the only switch over them. the lookup is a bit set resolved once at startup rather than a name per rule per file, because the engine's gate functions walk all fifty rules on every file and a string compare there would land on the scan's hot path. every rule still runs by default, so a project that names nothing reports exactly what it reported before

### Bug Fixes

* stop crashing on a brace pair inside a template's `${...}` substitution: the `${` container was lexed without counting the braces inside it, so a substitution holding an object literal (`\`${scoreOf({ id })}\``) ended the container at the object literal's `}`, stranded every token after it, and left them as unparented nodes. `grimuah check` then aborted on a core dump before reporting a single row. a template's substitution is now lexed to the brace that closes the container rather than to the first brace it meets
* stop crashing on a function type written where the annotation owns a body: a class member's own annotation (`private handler: (value: number) => number;`), a method's, a getter's or an object literal method's return annotation (`m(): (value: number) => number { ... }`) ended the type at the `=>` that belongs to the type, so the annotation's tail was re-read as class member syntax, the unmodelled node was left unparented, and `grimuah check` aborted on a core dump before reporting a single row. a return annotation now ends at the `{` that starts the body and a `=>` inside it is part of the type, a member's own annotation ends at the `=` that introduces its value, and a parameter's annotation ends at the default's `=` rather than at a `=>`, which used to leave the type's tail as a second parameter's name. an object *type* in a return position and an arrow whose own return annotation spells a function type read exactly as they did, both known gaps
* keep a declarator's initializer when its own type annotation spells a function type: `const assert: (condition: boolean, message: string) => asserts condition = (condition, message) => { ... }` stopped the annotation at the `=>` that belongs to the type rather than at the `=` that introduces the value, so the declaration ended at its annotation, the arrow after it was re-parsed as a stray statement, and the whole file reported an unmodelled node. the annotation now ends at the `=` and a `=>` inside it is part of the type, so the initializer attaches and the `.unknown` node is gone. 22 of `no-duplicated-function-body`'s 82 sites over the research corpus were invisible before this
* the research runner hands a detector the file's own path, so a detector that looks the project's `architecture.config.json` up can run at all: `no-redundant-allowed-import` threw before printing its first row, and a rule that reads the project's configuration had no way to be checked against the live detector
* stop scaffolding dead config: the presets and the `add` and `init` generators no longer write an `allowedImports` entry that the DAG already implies. a grant to a surface with a lower dagOrder comes from the graph itself, so all 42 entries in the shipped presets were entries `canImport` never read, and every config those presets generated carried them too. a same-dagOrder or a shallow-to-deep grant is still written down
* read JSX files again: a self-closing element consumed every byte after it, and a binding referenced only by a tag looked unreferenced, so `noUnusedImports` and `noUnusedVariables` now work on `.tsx` and `.jsx`
* report the escapes from two shipped bans: `as any[]` (and `as any | T`) is a `as any` cast, and `export * from` is a proxy re-export
* warn when a configured surface's directory is absent, where a typo in `architecture.config.json` used to disable the whole surface in silence
* keep a project's declared `sourceRoots` when a surface is removed: `grimuah remove` rebuilds `architecture.config.json` by hand and wrote the surfaces and the layers while leaving the roots behind, so a project that names its roots lost the declaration the first time it removed a surface. `add`, `remove` and `upgrade` now write every section they do not own, and the e2e suite asserts a rewrite keeps both the roots and the rule toggles
* scaffold a project with every strictness knob a compiler default does not carry: `init` wrote a `tsconfig.json` naming `noImplicitOverride`, `noImplicitReturns`, `noPropertyAccessFromIndexSignature` and `noFallthroughCasesInSwitch` while leaving `exactOptionalPropertyTypes` off, so a property declared optional could still be handed an explicit `undefined` and every guard written against it had a state the type said could not exist. the template now states it, the e2e suite pins the key, and a fresh scaffold of all five presets typechecks with no errors. the rule research also listed `strict` as missing here, and that half is stale: TypeScript 6.0 defaults `strict` to true, which the template's own e2e assertion already recorded, so the key stays implicit and only the flag the default does not cover was added
